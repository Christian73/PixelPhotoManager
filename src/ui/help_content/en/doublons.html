Duplicate detection

PixelPhotoManager spots visually similar photos even when they have been resized, lightly edited or cropped.

When the detection happens

Detection is automatic and continuous: it starts after every scan of the library, with no button to click and no completion report. It runs in the background on a fraction of the CPU cores, and the application stays fully usable.

  • The analysis is incremental: only new or modified photos are compared against the rest of the library. Later passes are therefore far quicker than the first one.
  • Groups appear as they are found, without waiting for the end of the analysis.
  • Tools › Duplicate status… shows a snapshot: number of groups and of photos involved, date of the last check, and — if a pass is running — a live progress bar. Two buttons: View the groups and Check now (to force an immediate pass).
  • If unreadable files are encountered, a ⚠ N corrupted files counter appears in the status bar; clicking it opens the list.

How it works — two passes

PassTechniqueCases covered
1 — pHashPerceptual fingerprint (Hamming) Exact, resized and lightly edited duplicates (colour, brightness)
2 — ORB + RANSACKey-point matching Cropped duplicates (up to ~60 % of the area cut away) — only for the photos not grouped by pass 1

Note: Videos are not analysed for duplicates.

Duplicate badge

  • Thumbnails belonging to a duplicate group show a ⧉ badge.
  • Clicking that badge opens a view listing every photo of the group side by side.

Grid of duplicate groups  (“Duplicates” button in the sidebar)

The Duplicates button in the sidebar (the badge shows the number of groups) opens a dedicated grid listing every duplicate group at once: one card per group, a thumbnail of the first copy, and the number of copies.

  • Double-click a card: opens the copies of the group in the viewer for a quick comparison.
  • ✕ on a card: dissolves the whole group (no file is deleted). The decision is persistent: that group will never be formed again as long as none of its members changes. A new file similar to one of them is still detected normally.
  • Check now button at the top of the grid to force an immediate pass.

Recommended workflow

  • Let the detection happen: the ⧉ badges appear by themselves on the thumbnails concerned, as the analysis progresses.
  • Click a badge to examine the group of similar photos.
  • Select the copies to keep / delete, then press Del.

Deleting a duplicate sends the file to the Windows recycle bin (recoverable) — check the photos carefully before confirming.

Corrupted files found during the analysis

If a file cannot be read during the analysis (damaged JPEG, interrupted copy…), it is reported rather than silently skipped. Two ways in: the ⚠ N corrupted files counter in the status bar, and Tools › Corrupted files… — which offers List… (the list of files, where you can target only some of them) and Repair….

  • A confirmation is asked for before any repair attempt.
  • PixelPhotoManager tries to save a clean copy of the file using a decoder more tolerant than the one used for the analysis.
  • The original is always backed up before being modified (hidden .tmp_originals folder next to the file), and the Windows modification and creation dates are preserved exactly.
  • A Repair finished summary lists the files repaired, then those that could not be (corruption too severe). For the latter only, a Delete these files… button is offered — deletion goes through the Windows recycle bin, and the paths stay available afterwards through Tools › Deleted corrupted files….

Tools › Problem history… keeps a record of every analysis that ran into corrupted files (date, number found, number repaired) with direct access to the list of files that were not repaired.
