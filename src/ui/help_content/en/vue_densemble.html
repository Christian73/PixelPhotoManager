PixelPhotoManager

Non-destructive photo and video manager for Windows. Every edit is stored separately — the original is never modified.

Tip: this help window has a search bar at the top (Ctrl+F puts the cursor in it). It searches the tab you are reading and then, if needed, the following ones — the tab holding the first result is selected automatically and the passage is highlighted. Enter jumps to the next match.

How the interface is laid out

  • Left sidebar — watched folders, albums, identified people, and at the top an instant filter box by file name, camera make/model, folder or person (F9 shows/hides the sidebar).
  • Central grid — thumbnails of the photos and videos in the selected context.
  • Viewer — opened by double-clicking a thumbnail; editing panel on the left.
  • Bottom bar — number of files, size, zoom slider for the grid.

Grid display modes

  • Grid mode — uniform thumbnails, size adjustable with the slider at the bottom right.
  • Timeline mode — a time ribbon: 5 rows growing towards the centre. The central photo is the “current” one. Move around with the wheel, the arrow keys or the scroll bar on the right. The slideshow starts from that central photo.

Supported formats

Images: JPEG, PNG, TIFF, WebP, BMP, GIF, HEIC/HEIF, RAW (CR2, NEF, ARW, DNG, ORF, RW2).
Videos: MP4, MOV, AVI, MKV, WMV, WebM, M4V, 3GP, FLV, TS, MTS, MPG, MPEG.

Note: a RAW file is displayed and exported at the resolution of the JPEG preview embedded by the camera (not a full demosaic of the sensor data).

Where your data is stored

Everything lives in %LOCALAPPDATA%\PixelPhotoManager\

File / FolderContents
catalog.dbPhoto/video index (paths, EXIF, metadata)
thumbnails.dbCache of the generated thumbnails
edits.dbEvery edit and its history
faces.dbDetected faces, embeddings, clusters and identified people
dedup_cache.dbDuplicate analysis cache (fingerprints, comparisons already made)
config.jsonWatched folders and preferences
faces_backups\Time-stamped backups of the face recognition (visages_YYYYMMDD_HHMMSS.zip)
problems_history.jsonlHistory of the corrupted files found/repaired during the duplicate analyses

Your original files are never modified. Deleting edits.db wipes out every edit; deleting catalog.db forces a full reindex.
