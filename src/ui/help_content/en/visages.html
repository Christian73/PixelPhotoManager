Face detection and recognition

The recognition pipeline runs in three steps:

① Analyse (automatic)  →  ② Group  →  ③ Identify

Only steps ② and ③ require anything from you. The options below are presented in the order in which they appear in the Faces menu. Read the descriptions before using one: some of them are long.

① Analyse the faces  (automatic, no action required)

What it does: As soon as a library scan finds new photos, the analysis starts automatically in the background: InsightFace (buffalo_l model) detects the faces and computes a 512D ArcFace vector for each one. When it finishes, grouping also starts automatically. Progress is shown in the status bar.

Scope: Only the photos that have never been analysed (new photos added to the library). Photos already processed are skipped, even if they contain faces marked “ignored”.

Duration: from a few seconds (a new photo) to several hours (the first analysis of a large library). The application stays usable throughout.

Picasa import  (Faces › Import from Picasa…)

  • Imports the face annotations from Google Picasa's .picasa.ini files: names and face regions.
  • Names are matched automatically to existing people, or create new people.

Do this only once. A new import re-inserts every Picasa name and annotation already known, which can create duplicates or bring back associations you had removed. A warning is shown if you try to run the import again.

Reset and reindex  (Faces › Reset and reindex…)

Two options to choose from, to be used with care:

OptionWhat is erasedWhat is kept
Reset clustering HDBSCAN groups only Embeddings, names and person ↔ face associations
Full reindex Everything (embeddings, groups, names, associations) — (clean slate)

A full reindex takes several hours depending on the size of the library. Make a backup first.

② Group the faces  (Faces › Group faces…)

What it does: Groups by similarity the faces that have already been analysed, using the HDBSCAN algorithm on the ArcFace vectors. The groups are then presented in Identify the people…

Scope: Every face with a stored embedding, except those already identified (person_id assigned). Confirmed associations are kept intact.

What it does NOT do:

  • It does not run InsightFace detection again.
  • It does not erase names or associations already confirmed.
  • It does not process faces marked “ignored”.

Duration: 15 to 30 minutes depending on the size of the library. Run it again after adjusting the similarity tolerance in the Settings.

As soon as new groups are formed, the application automatically compares the centroid (average embedding) of each one to the people already named. Three confidence tiers, according to the cosine similarity with the closest person:

SimilarityEffect
≥ 70 %Automatically assigned to the person, without confirmation
≥ 55 %Suggestion recorded: the group appears under “Awaiting verification” in the view of the person concerned — see step ③ below
≥ 50 %A “Probably X” label (blue) shown as a preview in the identification popup, without a suggestion being recorded yet

This comparison is silent and never runs InsightFace again. Below 70 %, no face is ever associated with a person without your approval.

Error review  (Faces › Error review…)

What it does: Lists the photos for which step ① (analysis) failed — a timeout or a crash of the detection subprocess — with a thumbnail, the file name and the type of error. The ⟳ Retry button runs the analysis again for that single file; the row disappears from the list as soon as processing succeeds.

Scope: Only the photos in error. As long as a photo stays in error, it is excluded from the following automatic analyses (it is not retried on every scan).

These photos can also be spotted directly in the grid: right-clicking a thumbnail in error offers the “Retry face identification” option in the context menu.

Backup and restore

  • Faces › Back up recognition data… — creates a timestamped backup of the whole faces.db (embeddings, groups, people, annotations).
  • Faces › Manage backups… — lists, restores or deletes the backups. The current state is automatically backed up before any restore.

Counters  (Faces › Counters…)

Shows a numerical summary of the face recognition: number of people identified, of faces identified / recognised / awaiting confirmation / unknown, as well as the counters related to the Picasa import. Nothing is started — it is a plain status report.

③ Identify the people  (“Identify…” button in the sidebar)

The Identify… button in the sidebar (with a badge showing the number of groups awaiting attention) opens the view of the anonymous groups so you can name them. An unidentified group can show a suggested name, according to its resemblance to a person already named:

  • “Probably X” (blue) — similarity ≥ 50 %
  • “Maybe X” (grey) — similarity ≥ 45 %

Giving the same name to several groups merges them into the same person.

Nothing is started — this is pure navigation.

View of one person's faces

Click a person in the sidebar to open their detailed view. It shows two sections:

  • Confirmed faces — faces already associated with this person.
    • Single click: select a face.
    • Ctrl+click: multiple selection. Shift+click: range selection.
    • Double-click: open the matching photo in the viewer.

Right-click on a confirmed face:

ActionEffect
ReassignMoves the selected face or faces to another person
UnassignRemoves the face from the person; it is reconsidered for other people
Use as the main thumbnailUses this face as the avatar in the sidebar
  • Awaiting verification — groups the system suggests associating with this person.
    • Hover a thumbnail to reveal ✓ (accept) and ✗ (reject).
    • Right-click: accept or reject the whole group.
    • Accept all / Reject all buttons in the header of the section.

A rejected face is never lost: it stays isolated and remains a candidate for a suggestion for other people.

Managing people (sidebar)

  • Named people appear in the sidebar under People.
  • An orange badge between the thumbnail and the name shows the number of pending suggestions.
  • In the viewer, the Faces panel lists the faces of the open photo.

Right-click on a person in the sidebar:

ActionEffect
Rename…Changes the name throughout the library
Merge with…Merges every face of this person with those of another
Clear the name…Removes the name — the faces become anonymous groups again

Ignored faces

A face can be ignored in two ways:

  • Automatically during detection: size below the proportional threshold, or confidence score < 0.65. The face is stored but excluded from clustering.
  • Manually with the ✕ button in the Faces panel (false positive, stand-in, background). The face stays recoverable through Ignored faces… (below).

The Ignored faces… button at the bottom of the Faces panel lets you see and restore the ignored faces photo by photo.
